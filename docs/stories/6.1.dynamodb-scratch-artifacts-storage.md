# Story 6.1: DynamoDB Scratch Artifacts Storage

## Status

Approved

## Story

**As the** system  
**I need** reliable artifact storage with idempotency  
**So that** race conditions don't corrupt data

## Acceptance Criteria

**Table: scratch_artifacts**

**Schema:**
1. Table created with partition key: job_id (String, UUID)
2. Sort key: task_id#artifact_version (String, e.g., "cfp_extract#v0001", "cfp_extract#v0002")
3. **No GSIs** for MVP (explained below)
4. Billing mode: On-demand (artifacts are variable size, unpredictable access patterns)
5. Point-in-time recovery: Enabled (for audit trail and data recovery)

**Why No GSIs:**
6. scratch_artifacts is designed for **per-job retrieval**, not cross-job analytics
7. Primary access pattern: Query by job_id to reconstruct workflow
8. GSIs would need different partition keys; since base table uses job_id, GSIs provide minimal value
9. **Analytics queries** (e.g., "all CFP Extractor artifacts", "timeout rates by sub-worker") come from:
   - Decision events in decision_events_by_job table (from Story 3.1)
   - Precomputed aggregates in daily_metrics table (from Story 6.2)
   - NOT from querying scratch_artifacts across jobs
10. **Design Principle:** scratch_artifacts = workflow reconstruction and artifact retrieval for single jobs; decision_events + generation_metrics + daily_metrics = analytics and cross-job queries

**Attributes (Standard Envelope):**
11. Standard artifact envelope structure (from architecture/data-models.md):
    - meta: {artifact_id, job_id, iteration, parent_task_id, task_id, worker_id, worker_vendor, worker_model, artifact_type, artifact_version, schema_version, spawned_at, completed_at, status}
    - data: {artifact-specific data, may be summary if large}
    - quality_signals: {confidence, coverage, validation_passed}
    - provenance: {sources[], claims[], tool_calls[]}
    - overflow: {s3_payload_ref, s3_tool_results_ref, payload_sha256, payload_size_bytes}
    - execution: {tokens_used, execution_time_ms, error}
12. All required fields validated before write (from Story 6.4 schema validation)

**Idempotency Rules (CRITICAL - Deterministic Versioning):**
13. Sort key uses stable task_id + zero-padded version: `task_id#v0001`, `task_id#v0002`, `task_id#v0003` (zero-padded to 4 digits for lexicographic sorting)
14. task_id represents "the conceptual task" (e.g., "cfp_extract", "evidence_research", "draft_generation", "red_team_review")
15. artifact_version increments for retries with different content (zero-padded: "v0001", "v0002", etc.)
16. Every Lambda write uses ConditionExpression: `attribute_not_exists(job_id)` (PK/SK pair defines uniqueness, this prevents overwriting)
17. **Retry behavior (deterministic, content-aware):**
    - Writer computes content_hash: SHA-256 hash of artifact data (deterministic, excludes timestamps)
    - First attempt: Try write to `task_id#v0001` with ConditionExpression
    - If ConditionExpression fails (item exists): GetItem to retrieve existing artifact
      - Compare stored content_hash with new content_hash
      - **Same hash:** Return existing artifact_id (idempotent read, no-op)
      - **Different hash:** Try write to `task_id#v0002` with ConditionExpression
        - If v0002 exists: Compare hashes, if different try v0003, etc. (increment until unique)
    - **Advantage:** Writer handles version selection automatically based on content hash comparison
18. Never create duplicate artifacts with same sort key
19. Log all duplicate write attempts (same content hash) as `duplicate_write_attempt` decision events (from Story 3.1)
20. **Advantage:** No inventing new task_id strings mid-stream; stable task identifiers with explicit versioning; automatic version selection based on content

**Size Management:**
21. If artifact size < 350KB: Write full artifact to DynamoDB data field
22. If artifact size >= 350KB:
    - Write summary (max 10KB) to DynamoDB data field
    - Upload full artifact to S3: `s3://scratch-artifacts/{job_id}/{task_id}/{artifact_version}/full_artifact.json` (includes artifact_version to prevent overwriting across versions, from Story 6.3)
    - Set overflow.s3_payload_ref = S3 key
    - Calculate and set overflow.payload_sha256 (SHA-256 hash of full artifact)
    - Set overflow.payload_size_bytes = actual size before compression/overflow
23. Tool results: Always store summary in provenance.tool_calls[].results_summary (50-200 chars, from Story 3.3)
24. If tool results >50KB: Upload to S3, set overflow.s3_tool_results_ref (per-tool pointer in provenance.tool_calls[], from Story 3.3)
25. **S3 key immutability:** S3 keys include artifact_version to prevent overwriting across versions (each version has its own S3 object)

**Access Patterns:**
25. Get all artifacts for job: Query by job_id (returns all task_ids with all versions)
26. Get specific artifact: GetItem by job_id + task_id#artifact_version (e.g., "cfp_extract#v0001")
27. Get latest artifact version: Query by job_id, filter by task_id prefix using `begins_with(SK, "task_id#")`, sort by SK descending (lexicographic, zero-padded versions ensure correct ordering: v0002 > v0001), limit 1
28. **Optional enhancement:** Store "latest pointer" item: SK = `task_id#LATEST` containing `latest_version` and `latest_artifact_id` for cheap reads (hot path optimization)
29. Get full artifact if overflowed: Check overflow.s3_payload_ref, fetch from S3 (from Story 6.3)

**Integration with Story 2.3:**
29. Sub-worker artifact writer uses this table (from Story 2.3)
30. Idempotency: If artifact already exists (ConditionExpression fails), GetItem and return existing artifact (only if schema_version matches, from Story 2.3)
31. Validation: All artifacts validated before write (from Story 6.4)
32. If validation fails: Do NOT write artifact, return validation error (from Story 2.3)

### Technical Constraints

**Table Design:**
- No GSIs: scratch_artifacts is for per-job retrieval only, analytics from decision_events/daily_metrics
- Billing mode: On-demand (variable size, unpredictable access patterns)
- Point-in-time recovery: Enabled (for audit trail and data recovery)

**Idempotency:**
- ConditionExpression: `attribute_not_exists(job_id)` (PK/SK pair defines uniqueness, this prevents overwriting)
- **Content-aware versioning:** Writer computes content_hash (SHA-256 of artifact data), compares with existing artifacts
  - Same content hash: Return existing artifact_id (idempotent read, no-op)
  - Different content hash: Increment artifact_version (v0001 → v0002 → v0003, etc.) and retry write
- Deterministic versioning: task_id#v0001, task_id#v0002, etc. (zero-padded to 4 digits for lexicographic sorting, stable task identifiers with explicit versioning)
- Log duplicate_write_attempt decision events (same content hash, from Story 3.1)

**Size Management:**
- DynamoDB limit: 400KB item size
- Threshold: 350KB (write summary to DynamoDB, full artifact to S3)
- Summary: Max 10KB in DynamoDB data field
- S3 upload: `s3://scratch-artifacts/{job_id}/{task_id}/{artifact_version}/full_artifact.json` (includes artifact_version to prevent overwriting across versions, from Story 6.3)
- SHA-256 hash: Calculate and store for integrity verification
- **S3 key immutability:** Each artifact version has its own S3 object (no overwriting across versions)

**Validation:**
- All artifacts validated before write (using shared schema validator from Story 6.4)
- If validation fails: Raise ArtifactValidationError, do NOT write artifact
- Schema version check: If existing artifact has different schema_version, raise SchemaVersionMismatchError

**Access Patterns:**
- Get all artifacts for job: Query by job_id
- Get specific artifact: GetItem by job_id + task_id#artifact_version (e.g., "cfp_extract#v0001")
- Get latest artifact version:
  - **Option 1 (fast, optional):** GetItem by job_id + `task_id#LATEST` to get latest_version pointer, then GetItem by job_id + task_id#latest_version
  - **Option 2 (fallback):** Query by job_id, filter by task_id prefix using `begins_with(SK, "task_id#")`, sort by SK descending (lexicographic, zero-padded versions ensure correct ordering: v0002 > v0001), limit 1
- Get full artifact if overflowed: Check overflow.s3_payload_ref, fetch from S3 (from Story 6.3)
