# Story 1.3: Results Display & User Feedback

## Status

Approved

## Story

**As a** conference speaker  
**I want to** quickly see the final abstract and provide feedback  
**So that** I can evaluate quality and signal my intent

## Acceptance Criteria

1. Verdict tab (renamed from "Results") shows clean display of final abstract title and content
2. Iteration selected by Manager is displayed (0-4)
3. Vendor assignments shown (Manager: X, Worker: Y)
4. Output Artifact section: Abstract title, content, copy/download functionality
5. Human Verdict (Quality) section - Primary feedback:
   - 👍 Accept button (labeled: "This abstract is usable as a starting point")
   - 👎 Reject button (labeled: "Not usable / low quality")
   - Optional quality rating: 4-point rubric (Strong, Adequate, Weak, Bad) - nice-to-have, not required
6. Submission Intent (optional): Radio buttons "Would submit with edits" | "Would not submit"
7. Why section - Secondary feedback:
   - Optional comment field (max 500 chars)
   - Observability helpful question: "Did the workflow view help you understand why the output is good/bad?"
     - Options: Yes / Somewhat / No (optional but recommended)
8. Feedback submission triggers confirmation message
9. Abstract is copyable (select + copy works)
10. Download button for abstract (plain text)
11. Verdict tab accessible immediately after generation completes

### API Specifications

**Submit Feedback Endpoint:**
- Endpoint: `POST /api/v1/feedback/{job_id}?token={job_read_token}`
- Authentication: Requires `job_read_token` (query param or Authorization header)
- Request Format:
  - Content-Type: `application/json`
  - Body: `{ accepted: boolean, intent?: string, comment?: string }`
- Response Format:
  - Status: `200 OK`
  - Content-Type: `application/json`
  - Body: `{ job_id: string, feedback_recorded: boolean, timestamp: string }`
- Error Responses:
  - `400 Bad Request`: Invalid request body (validation errors)
  - `403 Forbidden`: Token missing or invalid
  - `404 Not Found`: Job not found
  - `500 Internal Server Error`: Server error

**Validation Rules:**
- `quality_verdict`: Must be 'accept' | 'reject' (required) - maps to `accepted: boolean` for API
- `quality_rating`: Optional, must be 1-4 if provided (Strong=1, Adequate=2, Weak=3, Bad=4)
- `submission_intent`: Optional, must be one of ['would_submit_with_edits', 'would_not_submit'] if provided (only if quality_verdict === 'accept')
- `observability_helpful`: Optional but recommended, must be one of ['yes', 'somewhat', 'no'] if provided
- `comment`: Max length 500 characters

[Source: docs/prd/api-specifications.md#API-3]

**Get Job Status Endpoint:**
- Endpoint: `GET /api/v1/status/{job_id}?token={job_read_token}`
- Use to fetch completed job result if not already in jobStore
- Returns full abstract data when `status === 'completed'`

[Source: docs/prd/api-specifications.md#API-2]

### Form Validation

**Validation Library:**
- React Hook Form 7.50.0 for form management
- Zod 3.22.0 for schema validation (used with React Hook Form resolver)

**Validation Rules:**
- `quality_verdict`: Required, must be 'accept' | 'reject' (must select Accept or Reject)
- `quality_rating`: Optional, must be 1-4 if provided (Strong=1, Adequate=2, Weak=3, Bad=4)
- `submission_intent`: Optional, but if provided must be one of ['would_submit_with_edits', 'would_not_submit'] (only if quality_verdict === 'accept')
- `observability_helpful`: Optional but recommended, must be one of ['yes', 'somewhat', 'no'] if provided
- `comment`: Optional, max 500 characters (enforce with character counter)

**Validation Schema:**
```typescript
import { z } from 'zod';

const feedbackSchema = z.object({
  quality_verdict: z.enum(['accept', 'reject']),
  quality_rating: z.enum([1, 2, 3, 4]).optional(),
  submission_intent: z.enum(['would_submit_with_edits', 'would_not_submit']).optional(),
  observability_helpful: z.enum(['yes', 'somewhat', 'no']).optional(),
  comment: z.string().max(500).optional(),
}).refine((data) => {
  // submission_intent only valid if quality_verdict === 'accept'
  if (data.submission_intent && data.quality_verdict !== 'accept') {
    return false;
  }
  return true;
}, {
  message: 'Submission intent can only be provided if quality verdict is accept',
});
```

**API Mapping:**
Frontend schema maps to backend API format:
- `quality_verdict: 'accept'` → `accepted: true`
- `quality_verdict: 'reject'` → `accepted: false`
- `submission_intent` → `intent` (same values)
- `observability_helpful` → New field (may need backend support)
- `quality_rating` → New field (may need backend support)

### Clipboard API

**Implementation:**
- Use `navigator.clipboard.writeText(text)` for modern browsers
- Fallback to legacy method (create temporary textarea, select, copy, remove)
- Handle errors gracefully (show error message if copy fails)
- Show success notification after copy

**Browser Compatibility:**
- Clipboard API: Chrome 66+, Firefox 63+, Safari 13.1+
- Fallback: All browsers (legacy method)

[Source: MDN Clipboard API documentation]

**Implementation:**
