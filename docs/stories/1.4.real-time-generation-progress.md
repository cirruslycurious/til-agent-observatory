# Story 1.4: Real-Time Generation Progress

## Status

Approved

## Story

**As a** user  
**I want to** see progress indicators during generation  
**So that** I know the system is working and how long it will take

## Acceptance Criteria

1. Loading spinner appears immediately after "Generate Abstract" clicked on LandingPage
2. Progress messages update every 5-10 seconds with human-readable messages:
   - "Manager formulating objectives..."
   - "Worker planning execution strategy..."
   - "Spawning sub-workers..."
   - "CFP Extractor analyzing conference style..."
   - "Evidence Researcher gathering recent trends..."
   - "Draft Generator creating candidates..."
   - "Red Team Reviewer validating quality..."
   - "Evaluator assessing conference alignment..."
   - "Manager evaluating output..."
3. Estimated time shown: "This typically takes 1-2 minutes"
4. Progress bar or percentage displayed (heuristic based on stage_index / stage_total)
5. If generation exceeds 3 minutes, message: "This is taking longer than usual, but still processing..."
6. WebSocket connection status indicator (green dot = connected, yellow = degraded, red = disconnected)
7. Graceful error message if generation fails (display error details, allow retry or return to landing)

### Data Models

**WebSocket Progress Message:**
```typescript
interface ProgressMessage extends BaseMessage {
  type: 'progress';
  job_id: string;
  stage: string; // Stage name (manager_goal, worker_planning, sub_worker_execution, etc.)
  message: string; // Human-readable message
  stage_index: number; // Current stage index (1-7)
  stage_total: number; // Total stages (7)
  timestamp: string; // ISO datetime
}
```

**Stage Mapping:**
- `stage_index: 1` → `manager_goal` → "Manager formulating objectives..."
- `stage_index: 2` → `worker_planning` → "Worker planning execution strategy..."
- `stage_index: 3` → `sub_worker_execution` → "Spawning sub-workers..."
- `stage_index: 4` → `evaluator` → "Evaluator assessing conference alignment..."
- `stage_index: 5` → `manager_evaluation` → "Manager evaluating output..."
- `stage_index: 6` → `decision` → "Finalizing selection..."
- `stage_index: 7` → `complete` → "Generation complete!"

**Sub-worker specific messages (within stage 3):**
- `cfp_extractor` → "CFP Extractor analyzing conference style..."
- `evidence_researcher` → "Evidence Researcher gathering recent trends..."
- `draft_generator` → "Draft Generator creating candidates..."
- `red_team_reviewer` → "Red Team Reviewer validating quality..."

**WebSocket Failed Message:**
```typescript
interface FailedMessage extends BaseMessage {
  type: 'failed';
  job_id: string;
  error: string; // Error message
  error_code?: string; // Optional error code
  timestamp: string; // ISO datetime
}
```

[Source: docs/prd/api-specifications.md#WebSocket-Protocol]

### API Specifications

**WebSocket Progress Messages:**
- Message type: `progress`
- Frequency: Every 5-10 seconds during active generation
- Contains: `stage`, `message`, `stage_index`, `stage_total`, `timestamp`
- Progress percentage: Heuristic calculation `(stage_index / stage_total) * 100`
- Note: Not true completion percentage (autonomous sub-worker spawning makes it non-deterministic)

**WebSocket Failed Messages:**
- Message type: `failed`
- Contains: `error` (string), optional `error_code`
- Triggers error display and job status update to 'failed'

**Connection State:**
- `connected`: WebSocket active and authenticated
- `degraded`: WebSocket disconnected, polling active
- `disconnected`: No connection, polling failed
- `polling-only`: WebSocket unavailable, using polling only

[Source: docs/frontend-architecture.md#WebSocket-Client, docs/frontend-architecture.md#WebSocket-+-Polling-Coordination]

### Technical Constraints

**Technology Versions:**
- React: 18.2.0
- TypeScript: 5.3.3
- Tailwind CSS: 3.4.0

**Critical Rules:**
- Never use `console.log` in production code - Use `logger` utility
- Progress percentage is heuristic, not true completion (document this clearly)
- Timeout warning should not block user interaction
- Error messages must be accessible (ARIA live regions)
- Connection status must update in real-time

[Source: docs/frontend-architecture.md#Critical-Coding-Rules, docs/architecture/coding-standards.md]

### State Management

**Job Store:**
- Use `jobStore.connectionState` for connection status
- Use `jobStore.jobStatus` for job state (queued, running, completed, failed)
- Track generation start time in component state or jobStore

**Progress State:**
- Store current progress message in component state or jobStore
- Calculate progress percentage from WebSocket `progress` messages
- Track elapsed time for timeout warning

[Source: docs/frontend-architecture.md#State-Management]

### WebSocket Integration

**Progress Message Handling:**
- Subscribe to `progress` messages via `useWebSocket` hook
- Update progress message display when `progress` message received
- Update progress bar percentage: `(stage_index / stage_total) * 100`
- Map stage names to human-readable messages

**Error Handling:**
- Subscribe to `failed` messages via `useWebSocket` hook
- Update jobStore status to 'failed'
- Display error message with details
- Provide retry or return actions

**Connection State:**
- Read `connectionState` from jobStore
- Update ConnectionStatus indicator when state changes
- Handle state transitions: connected → degraded → disconnected

[Source: docs/frontend-architecture.md#WebSocket-Client, docs/frontend-architecture.md#WebSocket-+-Polling-Coordination]

### Styling

**Tailwind CSS:**
- Use utility-first approach
- Theme colors: `obsidian`, `graphite`, `elevated`, `primary`, `secondary`, `muted`, `accent`, `success`, `error`
- Loading spinner: Animated, centered, appropriate size
- Progress bar: Thin, instrument-style (1-2px height), animated
- Connection status: Small dot (green/yellow/red), positioned appropriately
- Error message: Error color, clear messaging, action buttons

**Responsive Design:**
- Mobile: Progress indicators stack vertically
- Desktop: Can use horizontal layout if needed
- All indicators readable on small screens

[Source: docs/frontend-architecture.md#Styling-Guidelines]

**Real-time Updates:**

- Progress bar animates smoothly (CSS transitions)
- Connection status updates without flicker
- Timeout check runs every 10 seconds (not too frequent)

**Bundle Size:**
