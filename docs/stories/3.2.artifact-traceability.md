# Story 3.2: Artifact Traceability

## Status

Approved

## Story

**As an** AI developer  
**I want** complete artifact lineage and evidence chains  
**So that** I can trace how decisions were made

## Acceptance Criteria

**Standard Artifact Envelope (All Artifacts):**
1. All artifacts follow standard envelope structure (meta, data, quality_signals, provenance, overflow, execution)
2. All artifacts include sources array (non-empty, at least one source)
3. All artifacts include claims array (at least one claim)
4. Each claim has source_pointer that references an element in sources array (source_pointer must match sources[].source_pointer)
5. Tool calls include results_summary (50-200 chars), not full results
6. Full tool results stored in S3 if >50KB (via s3_tool_results_ref in overflow)
7. Artifacts >350KB: Summary in DynamoDB data field, full in S3 (via s3_payload_ref in overflow)
8. S3 references include SHA-256 hash for integrity (payload_sha256 in overflow)

**Artifact Dependency Tracking:**
9. System can reconstruct which artifacts fed which decisions
10. Worker's final abstract includes pointers to all input artifacts (in provenance.sources)
11. Artifact dependencies tracked via provenance.sources (each source with artifact_id enables dependency graph reconstruction)
12. Dependency graph queryable by job_id (returns all artifacts with their dependencies)
13. Circular dependency detection: If circular dependency detected, mark artifact status=invalid_dependency, exclude from final synthesis, log warning decision event (artifact_circular_dependency_detected)

**Artifact Validation:**
13. All artifacts validated against standard envelope schema before writing (pydantic validation, fails if invalid)
14. Validation enforces: sources array non-empty, claims array non-empty, each claim has valid source_pointer
15. Validation enforces: source_pointer format matches parseable grammar (from Story 3.1 evidence pointer grammar)
16. Validation enforces: Each source.id in provenance.sources is unique within the artifact
17. Claims granularity: Claims can be sentence-level, paragraph-level, or abstract-level assertions (scope not enforced, but documented for future validation)

**UI Integration:**
17. UI displays dependency graph in Deep View (visual tree showing which artifacts feed which)
18. Dependency graph shows artifact relationships (parent → child artifacts)
19. Evidence chains with clickable pointers to sources (source_pointer links resolve to source details)

**API Endpoints:**
20. `GET /api/v1/workflow/{job_id}/artifacts` returns all artifacts for a job (chronological order)
21. `GET /api/v1/workflow/{job_id}/artifacts/{artifact_id}` returns single artifact with full details (max 1-2MB payload by default, use ?full=true for unlimited)
22. `GET /api/v1/workflow/{job_id}/artifacts/dependencies` returns dependency graph (nodes and edges)

## Dev Notes

### Previous Story Insights

From Story 2.3 (Sub-Worker Spawning):
- Artifact envelope structure already defined: meta, data, quality_signals, provenance, overflow, execution
- Provenance structure: sources[], claims[], tool_calls[]
- Source pointer grammar: `artifact:{artifact_id}#path:{json_path}`, `web:{search_id}#result:{n}`, `conf:{conference}#abstract:{abstract_id}`
- Each source.id in provenance.sources must be unique
- Artifacts >350KB: Summary in DynamoDB, full in S3
- Tool results >50KB: Summary in DynamoDB (max 2-4KB), full in S3

From Story 1.2 (Dual-Layer Workflow Visualization):
- Artifact dependency graph component already planned: `ArtifactDependencyGraph.tsx`
- Deep View should display dependency graph (visual tree)
- Evidence chains with clickable pointers to sources

From Story 3.1 (Decision Event Capture):
- Evidence pointer grammar standardized: `ddb`, `artifact`, `web`, `conf`, `s3` types
- Source pointer format: `{type}:{identifier}[#{fragment}]`
- Allowed chars: `a-zA-Z0-9`, `-`, `_`, `#`, `/`, `:`, `.`
- Max 200 chars per pointer, max 10 pointers per event

**Key Insight:** Artifact traceability builds on the artifact envelope structure from Story 2.3 and the evidence pointer grammar from Story 3.1. This story ensures complete lineage tracking and dependency graph reconstruction.

### API Specifications

**Artifact Retrieval Endpoints:**
- **Endpoint:** `GET /api/v1/workflow/{job_id}/artifacts?token={job_read_token}`
- **Authentication:** job_read_token verified via token hash lookup
- **Response:** 
  ```json
  {
    "artifacts": [
      {
        "meta": {...},
        "quality_signals": {...},
        "provenance": {
          "sources": [...],
          "claims": [...]
        },
        "overflow": {
          "s3_payload_ref": "...",
          "payload_sha256": "..."
        }
      }
    ],
    "total": 15,
    "next_token": "optional pagination token"
  }
  ```
- **Pagination:** Limit 50 artifacts per request, use `next_token` for subsequent pages
- **Sorting:** Artifacts returned in chronological order (by sort key)

- **Endpoint:** `GET /api/v1/workflow/{job_id}/artifacts/{artifact_id}?token={job_read_token}[&full=true]`
- **Authentication:** job_read_token verified via token hash lookup
- **Query Parameters:**
  - `full=true` (optional): Return full artifact with no size limit
  - Default: Return artifact with max 1-2MB payload (truncate data field if needed, include `data_truncated: true` flag)
- **Response:** Full artifact (including full data if from S3, subject to size limits)
  - Always includes `payload_size_bytes` for UI awareness
- **S3 Integration:** If artifact has `s3_payload_ref`, fetch full payload from S3 and include in response
- **404:** Return 404 if artifact not found

- **Endpoint:** `GET /api/v1/workflow/{job_id}/artifacts/dependencies?token={job_read_token}`
- **Authentication:** job_read_token verified via token hash lookup
- **Response:**

### Technical Constraints

**Artifact Validation:**
- All artifacts must pass validation before writing to DynamoDB
- **Worker final abstract validation:**
  - Feature flag: `STRICT_LINEAGE_MODE` (environment variable)
  - If `STRICT_LINEAGE_MODE=true`: Block final abstract write if missing artifact pointers (fail validation)
  - If `STRICT_LINEAGE_MODE=false` (default): Log validation failure as warning (non-blocking, abstract still written)
  - Log warning decision event: `worker_final_abstract_missing_pointers` if validation fails
- Validation failures are blocking for sub-workers (artifact write fails if invalid)

**Dependency Graph Construction:**
- Dependency graph built by parsing provenance.sources (source_pointer with "artifact:" prefix)
- Graph construction is O(n) where n = number of artifacts (single pass through artifacts)
- **Circular dependency handling:**
  - If circular dependency detected: Mark affected artifacts with `meta.status="invalid_dependency"`
  - Exclude artifacts with `invalid_dependency` status from final synthesis (Worker skips them)
  - Log warning decision event: `artifact_circular_dependency_detected` (ties back to Story 3.1)
  - Circular dependencies should not occur (artifacts created sequentially), but handled deterministically if detected

**S3 Integration:**
- Full artifact payloads fetched from S3 on-demand (lazy loading)
- S3 keys: `{job_id}/{task_id}/full_artifact.json` or `{job_id}/{task_id}/tool_results.json`
- SHA-256 hash verification: Verify payload_sha256 matches downloaded content

**API Response Size Protection:**
- Default: Return artifact with max 1-2MB payload (truncate data field if needed, include `data_truncated: true` flag)
- If `?full=true` query parameter: Return full artifact (no size limit)
- Always include `payload_size_bytes` in response for UI awareness
- Prevents accidental UI footguns (large payloads causing browser crashes)

**Performance:**
- Dependency graph construction: Query all artifacts for job_id (single DynamoDB query)
- Graph size: Typical jobs have 5-15 artifacts (not a performance concern)
- API pagination: Limit 50 artifacts per request for `/artifacts` endpoint
