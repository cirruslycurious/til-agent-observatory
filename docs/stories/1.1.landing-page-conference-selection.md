### Data Models

**Generate Request:**
```typescript
interface GenerateRequest {
  conference: 'black_hat' | 'reinvent' | 'kubecon' | 'gartner_symposium' | 'google_cloud_next';
  topic: 'ai_ml_genai' | 'security_zero_trust' | 'cloud_arch_infra' | 'k8s_containers' | 'platform_devops' | 'networking_mesh' | 'data_analytics' | 'leadership_governance';
  user_session_id?: string; // Optional, generated if not provided
}
```

[Source: docs/prd/api-specifications.md#API-1]

**Generate Response (202 Accepted):**
```typescript
interface GenerateResponse {
  job_id: string; // UUID
  job_read_token: string; // Token for accessing job data
  status: 'processing';
  estimated_time_seconds: number;
  websocket_url?: string; // Optional, deprecated (use auth message frame instead)
}
```

[Source: docs/prd/api-specifications.md#API-1]

**Note:** The API spec mentions `websocket_url` in response, but frontend architecture specifies connecting with `?job_id=...` only and sending auth message frame. The websocket_url field can be ignored or used as a fallback reference.

### API Specifications

**Endpoint:** `POST /api/v1/generate`

**Request Format:**
- Content-Type: `application/json`
- Body: `{ conference: string, topic: string, user_session_id?: string }`

**Response Format:**
- Status: `202 Accepted`
- Content-Type: `application/json`
- Body: `{ job_id: string, job_read_token: string, status: string, estimated_time_seconds: number }`

**Error Responses:**
- `400 Bad Request`: Invalid conference or topic
- `429 Too Many Requests`: Rate limited (too many requests)
- `503 Service Unavailable`: System disabled (maintenance mode or cost guardrails)

**Rate Limits:**
- Global API Gateway: 100 requests/minute per IP (all endpoints)
- /generate endpoint-specific: 10 generations/minute per IP (server-side guard)

[Source: docs/prd/api-specifications.md#API-1]

**API Client Configuration:**
- Use ApiClient from `packages/frontend/src/services/api/client.ts`
- ApiClient handles 202 Accepted, 204 No Content, and non-JSON responses
- ApiClient checks Content-Type before parsing JSON
- Use logger utility (not console.log) for error logging

[Source: docs/frontend-architecture.md#API-Client-Configuration]

### Routing

**Route Configuration:**
- Path: `/` (root)
- Component: `LandingPage`
- No route protection required (public demo MVP)

**Navigation Flow:**
1. User submits form on LandingPage (`/`)
2. Frontend calls `POST /api/v1/generate` with conference and topic
3. Backend returns `202 Accepted` with `job_id` and `job_read_token`
4. Frontend stores token in `sessionStorage` (key: `cab:job_token:<jobId>`)
5. Frontend navigates to `/generate/:jobId`

[Source: docs/frontend-architecture.md#Navigation-Flow]

**Storage Strategy:**
- Use `sessionStorage` (not `localStorage`)
- Key format: `cab:job_token:<jobId>`
- Save token immediately after `/generate` API response
- Token used for accessing job-specific endpoints

**Implementation:**
- Use `tokenStorage` utility from `packages/frontend/src/utils/tokenStorage.ts`
- Call `tokenStorage.save(jobId, token)` after API response
