## Acceptance Criteria

**Dashboard Page:**
1. Dashboard page accessible at `/dashboard/evaluator` route (public, same security as Story 5.1)
2. Page loads in <3 seconds (including data fetch)
3. Mobile responsive (works on 360px width minimum)
4. Uses Recharts library (lazy-loaded) for all chart visualizations
5. All metrics fetched from `/api/v1/dashboard/evaluator` endpoint (single API call for all metrics)

**Accuracy Metrics:**
6. Top-1 conference match rate: Percentage of jobs where `evaluator_top_3[0]` equals `request_context.conference` - **Target:** >50% - **Denominator:** `total_jobs_with_evaluator_result` (jobs with `evaluator_status === "completed"` AND `evaluator_top_3.length === 3` AND `evaluator_confidence_scores.length === 3` in generation_metrics summary) - **Numerator:** Those where `evaluator_top_3[0] === request_context.conference` - **Canonical source:** `generation_metrics` summary record (denormalized `evaluator_top_3` and `request_context.conference` fields) - **Note:** Truth label = `request_context.conference` (request-time label, not independently verified ground truth) - **Add note in API response:** "Truth label = request_context.conference (request-time label, not independently verified ground truth)"
7. Top-3 conference match rate: Percentage of jobs where `request_context.conference` is in `evaluator_top_3` array - **Target:** >70% - **Denominator:** `total_jobs_with_evaluator_result` (same definition as AC 6) - **Numerator:** Those where `request_context.conference IN evaluator_top_3` array - **Canonical source:** `generation_metrics` summary record (denormalized fields)
8. Confusion matrix table:
    - Rows: Actual conference (from `request_context.conference` in `generation_metrics`)
    - Columns: Predicted conference (from `evaluator_top_3[0]` in `generation_metrics`)
    - Cells: Count of jobs for each (actual, predicted) combination
    - **Conferences:** black_hat, reinvent, kubecon (snake_case enum, UI displays friendly labels) - **Hard requirement:** Enforce conference enum set in API - **Add `conference_enum: ["black_hat","reinvent","kubecon"]` to API response** - **Confusion matrix uses that list for row/column keys** - **Scatter/calibration can ignore unknown conferences safely (or bucket them as "other")**
    - **Response shape:** `confusion_matrix: {is_insufficient_data: boolean, conferences: string[], rows: Array<{actual: string, counts_by_predicted: Record<string, number>, row_total: number}>, column_totals: Record<string, number>, grand_total: number}` - **Never return null; return object with is_insufficient_data flag** - **FE can hide/label based on is_insufficient_data and the response stays structurally stable** - **is_insufficient_data = true if grand_total < insufficient_data_threshold (20)**
    - **Canonical source:** `generation_metrics` summary record (denormalized `evaluator_top_3` and `request_context.conference` fields)

**Confidence Calibration:**
9. Scatter plot: Confidence score (X-axis) × Actual match (Y-axis, binary: 1 if top_3[0] === request_context.conference, 0 otherwise):
    - X-axis: `evaluator_confidence_scores[0]` (top-1 confidence score, denormalized)
    - Y-axis: Binary outcome (1 = match, 0 = no match)
    - Color: By actual conference (black_hat, reinvent, kubecon)
    - Chart uses Recharts ScatterChart component (lazy-loaded) - **API returns scatter data grouped by conference:** `scatter_series: Array<{conference: string, points: Array<{confidence: number, actual_match: 0|1}>}>` - **FE renders one <Scatter data={...} /> per conference** (Recharts supports multiple series for coloring)
    - **Canonical source:** `generation_metrics` summary record (denormalized `evaluator_confidence_scores` and `request_context.conference` fields)
10. Calibration curve: Are 80% confidence predictions correct 80% of the time?
    - X-axis: Confidence bins (0-0.2, 0.2-0.4, 0.4-0.6, 0.6-0.8, 0.8-1.0)
    - Y-axis: Actual accuracy rate (percentage of predictions in that bin that were correct)
    - Ideal line: Y = X (perfect calibration)
    - Chart uses Recharts LineChart component (lazy-loaded)
    - **Bin boundaries (precise):** [0.0,0.2) [0.2,0.4) [0.4,0.6) [0.6,0.8) [0.8,1.0] - **Lower-inclusive, upper-exclusive, except last bin upper-inclusive** - **Write this once in notes/constants so tests match**
    - **Definition:** For each confidence bin, calculate actual accuracy = (count of correct predictions in bin) / (total predictions in bin) - **Denominator:** Total predictions in bin - **Numerator:** Correct predictions in bin (`evaluator_top_3[0] === request_context.conference`)
    - **Insufficient data:** Hide calibration bins with `sample_size < 5` (otherwise curve looks jagged and misleading) - **Include sample_size per bin in response**
    - **Canonical source:** `generation_metrics` summary record (denormalized `evaluator_confidence_scores` and `request_context.conference` fields)
11. Confidence distribution histogram:
    - X-axis: Confidence score bins (0-0.2, 0.2-0.4, 0.4-0.6, 0.6-0.8, 0.8-1.0)
    - Y-axis: Count of predictions in each bin
    - Chart uses Recharts BarChart component (lazy-loaded)
    - **Bin boundaries (precise):** [0.0,0.2) [0.2,0.4) [0.4,0.6) [0.6,0.8) [0.8,1.0] - **Lower-inclusive, upper-exclusive, except last bin upper-inclusive** - **Same as calibration curve**
    - **Canonical source:** `generation_metrics` summary record (denormalized `evaluator_confidence_scores[0]`)

**Disagreement Patterns:**
12. Table: When Evaluator disagrees with target conference:
    - Columns: Target conference (from `request_context.conference`), Evaluator Pick (from `evaluator_top_3[0]`), Frequency (count), Manager Override Rate (percentage)
    - **Manager Override Rate definition:** Percentage of jobs where Manager selected a different iteration than the one with highest evaluator confidence - **Denominator:** Jobs where Evaluator disagreed with target - **Numerator:** Jobs where Manager selected iteration != best_iteration_by_evaluator - **Canonical source:** `generation_metrics` summary record (denormalized `selected_iteration`, `best_iteration_by_evaluator`, `best_iteration_confidence` fields) - **Denormalized fields:** `best_iteration_by_evaluator` (iteration index with highest evaluator confidence), `best_iteration_confidence` (highest evaluator confidence score), `evaluator_top1_for_selected_iteration` (optional), `evaluator_top1_for_best_iteration` (optional) - **This makes override checks O(1) per job, no complex joins needed**
    - **Only show rows where Evaluator Pick != Target conference** (disagreements only)
    - Sortable columns: Target, Evaluator Pick, Frequency, Manager Override Rate
    - **Canonical source:** `generation_metrics` summary record (denormalized fields)
13. Analysis: Does Manager trust Evaluator or override often?
    - Display summary statistics:
      - Overall Manager Override Rate: Percentage of all jobs where Manager selected iteration != best_iteration_by_evaluator
      - When Evaluator agrees with target: Manager Override Rate (percentage)
      - When Evaluator disagrees with target: Manager Override Rate (percentage)
    - **Canonical source:** `generation_metrics` summary record (denormalized `selected_iteration`, `best_iteration_by_evaluator`, `evaluator_agreement` fields)
14. Correlation: Evaluator confidence × Manager acceptance rate:
    - Scatter plot: X-axis = `best_iteration_confidence` (highest evaluator confidence across all iterations, denormalized), Y-axis = Manager chose best iteration (binary: 1 if `selected_iteration === best_iteration_by_evaluator`, 0 otherwise) - **Definition:** Bin by `best_iteration_confidence`, compute rate that `selected_iteration === best_iteration_by_evaluator` - **Denominator:** Total jobs with evaluator confidence in bin - **Numerator:** Jobs where Manager selected iteration === best_iteration_by_evaluator - **Alternative interpretation:** This measures "trust in evaluator" - how often Manager chooses the iteration with highest evaluator confidence - **Note:** Requires denormalized `best_iteration_confidence` and `best_iteration_by_evaluator` fields
    - Chart uses Recharts ScatterChart component (lazy-loaded)
    - **Canonical source:** `generation_metrics` summary record (denormalized fields)

**Performance Metrics:**
15. Response time distribution histogram:
    - X-axis: Response time bins (0-10s, 10-20s, 20-30s, 30-40s, 40-50s, 50-60s, >60s)
    - Y-axis: Count of evaluations in each bin
    - **Target:** <60 seconds (p95)
    - Chart uses Recharts BarChart component (lazy-loaded)
    - **Bin boundaries (precise):** [0,10000) [10000,20000) [20000,30000) [30000,40000) [40000,50000) [50000,60000) [60000,∞) - **Lower-inclusive, upper-exclusive, except last bin upper-inclusive (>=60000)** - **>60s means response_time_ms >= 60000** - **50-60s means [50000, 60000)** - **Write this once in notes/constants so tests match**
    - **Denominator:** Jobs with `evaluator_response_time_ms != null` (exclude failed/timeout jobs without response time) - **Include `response_time_sample_size` in response** - **Units:** Histogram bins are in seconds, but `evaluator_response_time_ms` is in milliseconds - **Clarify units in API schema**
    - **Canonical source:** `generation_metrics` summary record (`evaluator_response_time_ms` field, denormalized)
16. Timeout frequency: Percentage of jobs with `evaluator_timeout = true` - **Target:** <5% - **Denominator:** `total_jobs_with_evaluator_request` (all jobs that requested evaluator, including timeouts) - **Numerator:** Those with `evaluator_timeout = true` - **Canonical source:** `generation_metrics` summary record (`evaluator_timeout` boolean field, denormalized)
17. Reasoning quality (sample review): Average manual review score (1-5 scale, if available) - **Optional for MVP, display "Not yet available" with tooltip** ("requires manual review data, not collected in MVP")

    - **Canonical source:** `generation_metrics` summary record (`evaluator_response_time_ms` field, denormalized)

## Dev Notes

### Previous Story Insights

From Story 2.4 (Evaluator Agent - Blind Assessment):
- Evaluator writes results to `evaluation_results` table (dedicated table for cleaner queries)
- Table schema: PK = `job_id`, SK = `evaluator_request_id`, status = "completed" | "failed"
- Fields: `top_3_conferences`, `confidence_scores`, `reasons`, `timestamp`, `tokens_used`, `cost_usd`
- Evaluator uses Amazon Nova via Bedrock
- Timeout: 1 minute maximum (Lambda timeout + Step Functions polling timeout)
- Evaluator must be idempotent (no application retries, but SQS may redeliver)

From Story 6.2 (DynamoDB Generation Metrics Storage):
- `generation_metrics` table stores summary records with `evaluator_result`, `evaluator_timeout`, `evaluator_response_time_ms`, `evaluator_agreement` fields
- `evaluator_agreement` is denormalized boolean (evaluator top-1 match equals `request_context.conference`)
- `request_context.conference` field stores the actual conference requested (truth label)

From Story 5.3 (Vendor Comparison Dashboard):
- `evaluator_agreement` is denormalized into `generation_metrics` summary for single-table queries
- Truth label: Match against `request_context.conference` (actual conference requested)

**Key Insight:** Evaluator analysis uses denormalized fields in `generation_metrics` summary record for fast queries (like Story 5.4). At job completion, write evaluator summary into `generation_metrics` summary record:
  - `evaluator_top_3`: Array of 3 conferences (from evaluation_results.top_3_conferences)
  - `evaluator_confidence_scores`: Array of 3 numbers (from evaluation_results.confidence_scores)
  - `evaluator_status`: "completed" | "failed" | "timeout" (from evaluation_results.status or evaluator_timeout)
  - `evaluator_tokens_used`: Number (from evaluation_results.tokens_used)
  - `evaluator_cost_usd`: Number (from evaluation_results.cost_usd)
  - `best_iteration_by_evaluator`: Number (iteration index with highest evaluator confidence)
  - `best_iteration_confidence`: Number (highest evaluator confidence score across all iterations)
  - `evaluator_top1_for_selected_iteration`: String (evaluator top-1 for Manager's selected iteration, optional)
  - `evaluator_top1_for_best_iteration`: String (evaluator top-1 for best iteration by evaluator, optional)
  - `evaluator_agreement`: Boolean (already denormalized, evaluator top-1 match equals request_context.conference)
  - `evaluator_timeout`: Boolean (already denormalized)
  - `evaluator_response_time_ms`: Number (already denormalized)
- **This enables single-table query on generation_metrics summary records for <3s SLA** (dashboard reads from summary, evaluation_results remains canonical truth for detailed analysis)
- **Alternative (not recommended):** Query evaluation_results table with GSI on date_partition + timestamp, then join to generation_metrics - **This is slower and more complex, so denormalization is preferred**

### API Specifications

**Evaluator Analysis Endpoint:**
- **Endpoint:** `GET /api/v1/dashboard/evaluator`
- **Authentication:** Simple read token (dashboard token from env var) OR feature flag - **Same security as Story 5.1**
- **Query Parameters:**
  - `date_from`: YYYY-MM-DD (optional, default: 30 days ago) - **Dashboard range defaults to last 30 days**
  - `date_to`: YYYY-MM-DD (optional, default: today)
- **Response:** JSON object with all evaluator analysis metrics (see Data Models section) - **Includes:** `generated_at` (ISO timestamp), `range: {start_date, end_date}` (date range used for aggregation, defaults to last 30 days)
- **Performance:** Response time <3 seconds (aggregation queries optimized using GSI2 on generation_metrics table and efficient queries on evaluation_results table)
- **Caching:** Client-side caching for 5 minutes (prevent excessive API calls)
- **Data range:** Uses last 30 days by default (or all time if <30 days of data)

### Technical Constraints

**Performance:**
- Dashboard page load time: <3 seconds (including data fetch)
- API response time: <3 seconds (aggregation queries optimized using GSI2 on generation_metrics table and efficient queries on evaluation_results table)
- Client-side caching: 5 minutes (prevent excessive API calls)

**Data Aggregation:**
- **Primary:** Query `generation_metrics` table (summary records, GSI2 by date_partition buckets) - **Single-table query for <3s SLA**
- **All evaluator data is denormalized into generation_metrics summary record:**
  - `evaluator_top_3`, `evaluator_confidence_scores`, `evaluator_status`, `evaluator_tokens_used`, `evaluator_cost_usd`
  - `best_iteration_by_evaluator`, `best_iteration_confidence`, `evaluator_top1_for_selected_iteration`, `evaluator_top1_for_best_iteration`
  - `evaluator_agreement`, `evaluator_timeout`, `evaluator_response_time_ms`
  - `request_context.conference`, `selected_iteration`
- Filter by date range and `evaluator_status === "completed"` for accuracy/calibration metrics
- Aggregate only summary records (record_type = "summary") from `generation_metrics` table
- **No joins needed - single-table query on generation_metrics summary records**

**Chart Library:**
- Use Recharts library (lazy-loaded via dynamic import)
- All charts must be responsive (adjust to container width)
- Charts must handle empty data gracefully (display "No data available" message)

**Statistical Calculations:**
- Top-1 match rate: Count where `evaluator_top_3[0] === request_context.conference` / total_jobs_with_evaluator_result (evaluator_status === "completed" AND evaluator_top_3.length === 3 AND evaluator_confidence_scores.length === 3)
- Top-3 match rate: Count where `request_context.conference IN evaluator_top_3` / total_jobs_with_evaluator_result (same definition)
- Calibration curve: For each confidence bin, actual accuracy = (correct predictions in bin) / (total predictions in bin) - **Bin boundaries:** [0.0,0.2) [0.2,0.4) [0.4,0.6) [0.6,0.8) [0.8,1.0] (lower-inclusive, upper-exclusive, except last bin upper-inclusive)
- Manager Override Rate: Percentage where Manager selected iteration != best_iteration_by_evaluator - **Tie-break rule:** Highest confidence wins; on tie, lowest iteration index wins
- Confidence × Manager acceptance: Bin by best_iteration_confidence, compute rate that selected_iteration === best_iteration_by_evaluator

**Mobile Responsiveness:**
- Dashboard must work on 360px width minimum
- Tables must be scrollable on mobile
- Charts must adjust to container width
