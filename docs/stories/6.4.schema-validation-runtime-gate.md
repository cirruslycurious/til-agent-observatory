# Story 6.4: Schema Validation as Runtime Gate

## Status

✅ **COMPLETE** (2026-01-14)

## Story

**As the** system  
**I need** schema validation before writing artifacts  
**So that** bad data doesn't enter the system

## Acceptance Criteria

**Shared Schema Validator Library:**
1. Centralized library created: `packages/shared/schema-validator/`
2. **Source of truth: JSON Schema files** (`.schema.json` files in `schemas/` directory)
3. Python implementation: `schema_validator.py` using `jsonschema` library (validates against JSON Schema files)
4. TypeScript implementation: `schema_validator.ts` using `ajv` library (validates against JSON Schema files)
5. Both implementations use the same JSON Schema files (no drift, single source of truth)
6. Imported by all Lambda functions that write artifacts (artifact writer, tool logger, sub-workers)
7. JSON schemas defined for each artifact type:
    - `style_profile_v1.schema.json` (CFP/Style Extractor output)
    - `evidence_bundle_v1.schema.json` (Evidence Researcher output)
    - `draft_candidates_v1.schema.json` (Draft Generator output)
    - `review_feedback_v1.schema.json` (Red Team Reviewer output)
8. Version-aware validation: Validates against `meta.schema_version` and `meta.artifact_type` fields
9. Schema lookup: `${meta.artifact_type}_${meta.schema_version}.schema.json` (deterministic, e.g., `style_profile_v1.schema.json`)
10. Schema files stored in `packages/shared/schema-validator/schemas/` directory
11. Schema versioning: When artifact structure changes, create new schema file (e.g., `style_profile_v2.schema.json`)

**Runtime Enforcement Logic:**
12. Validation happens BEFORE DynamoDB write (validation gate, not post-write check)
13. Validation function signature: `validate_artifact(artifact_data: dict) -> ValidationResult` (extracts `meta.artifact_type` and `meta.schema_version` from artifact_data)
14. ValidationResult includes: `is_valid: bool`, `errors: list[str]`, `warnings: list[str]`
15. If validation fails: Raise `ArtifactValidationError` with validation errors (do NOT write to DynamoDB)
16. If validation succeeds: Proceed with DynamoDB write
17. Validation is synchronous (no async validation, blocking write until validated)
18. Schema lookup: Load schema file `${meta.artifact_type}_${meta.schema_version}.schema.json` from `schemas/` directory

**Required Field Enforcement (Global - All Artifacts):**
19. `meta.artifact_id`: Always required (String, UUID format)
20. `meta.job_id`: Always required (String, UUID format)
21. `meta.iteration`: Always required (Number, 0-4)
22. `meta.parent_task_id`: Always required (String, nullable allowed for root artifacts)
23. `meta.task_id`: Always required (String)
24. `meta.artifact_type`: Always required (String, enum: "style_profile" | "evidence_bundle" | "draft_candidates" | "review_feedback")
25. `meta.schema_version`: Always required (String, e.g., "v1", "v2", "v3")
26. `provenance.sources[]`: Must be non-empty array (at least one source - includes upstream artifacts, tool calls, etc.)
27. `quality_signals.confidence`: Must be 0-1 number (inclusive)
28. `quality_signals.coverage`: Must be enum: "comprehensive" | "moderate" | "limited"

**Artifact Type-Specific Required Fields:**
29. `provenance.claims[]`: Required for `evidence_bundle` (must have at least one claim), optional for other artifact types (only required when artifact type asserts factual claims)
30. **Note:** `quality_signals.validation_passed` is NOT stored (redundant - if artifact is written, validation implicitly passed)

**Artifact Type-Specific Validation:**
31. Style Profile (`style_profile_v1`): Must include `data.tone`, `data.length_preference`, `data.key_phrases[]`; `provenance.claims[]` optional (may be empty if derived from CFP text only)
32. Evidence Bundle (`evidence_bundle_v1`): Must include `data.evidence_items[]` (non-empty), each with `source_pointer`, `relevance_score`; `provenance.claims[]` required (must have at least one claim)
33. Draft Candidates (`draft_candidates_v1`): Must include `data.candidates[]` (non-empty), each with `text`, `quality_score`; `provenance.claims[]` optional (sources/claims may exist indirectly)
34. Review Feedback (`review_feedback_v1`): Must include `data.feedback_items[]` (non-empty), each with `section`, `issue`, `severity`; `provenance.claims[]` optional (feedback based on draft and rubric, not factual claims)

**Worker Fallback Handling:**
29. If sub-worker produces invalid artifact, Worker receives `ArtifactValidationError`
30. Worker treats validation failure as if artifact is missing (equivalent to timeout)
31. Worker applies appropriate fallback strategy (same as sub-worker timeout handling)
32. Worker logs: "Sub-worker {type} produced invalid schema, applying fallback" (decision event: `sub_worker_validation_failed`)

**Validation Event Tracking:**
33. All `artifact_validation_failed` events logged to `decision_events_by_job` table (from Story 3.1)
34. Event includes: `job_id`, `task_id`, `artifact_type`, `schema_version`, `validation_errors[]`, `severity: "critical"`
35. Dashboard shows validation failure rate by sub-worker type (from `generation_metrics` table)
36. **CloudWatch alarm:** Alert if validation failure rate >5% for any sub-worker type:
    - [ ] Time window: 15 minutes (rolling window)
    - [ ] Minimum sample size: At least 20 attempts (to prevent spam from low-volume periods)
    - [ ] **Attempt definition:** A sub-worker invocation that returned any artifact (completed or failed) - counts as one attempt
    - [ ] **Failure definition:** A sub-worker invocation that produced an invalid artifact (validation failed) - counts as one failure
    - [ ] **Rate calculation:** (failures / attempts) * 100, only if attempts >= 20 in the 15-minute window
    - [ ] Alarm triggers if: rate >5% AND attempts >= 20 in the 15-minute window

**Schema Evolution:**
40. When artifact structure changes, create new schema version (e.g., `v1` → `v2`)
41. Old schema versions remain for backward compatibility (read-only validation of historical artifacts)
42. **Schema version enforcement:**
    - Writers default to latest schema version (exported as `LATEST_SCHEMA_VERSION_BY_TYPE` constant)
    - Writers may emit older versions only if explicitly configured (e.g., replay mode, backfill)
    - If artifact specifies `meta.schema_version` that is older than latest: Allow (backward compatible), but log warning or emit `artifact_schema_deprecated` event
    - If artifact specifies `meta.schema_version` that doesn't exist (future version): Hard fail with `ArtifactValidationError` (unknown schema version)
43. **Schema migration (explicit, not in runtime gate):**
    - Auto-migration kept out of runtime gate (at least for MVP)
    - If migration needed, do it as explicit step: `migrate_and_validate(artifact)` with clear events
    - Migrations must be small and deterministic
    - Runtime gate only validates, does not transform

**Error Messages:**
41. Validation errors must be human-readable (field path, expected type, actual value)
42. Error format: `"{field_path}: expected {expected_type}, got {actual_value}"`
43. Multiple errors returned as array (don't fail on first error, collect all errors)

## Dev Notes

### Previous Story Insights

From Story 6.1 (DynamoDB Scratch Artifacts Storage):
- Artifact envelope structure: meta, data, quality_signals, provenance, overflow, execution
- Schema validation happens BEFORE DynamoDB write (validation gate)
- Invalid artifacts are NOT written to DynamoDB (prevents bad data)

From Story 2.3 (Sub-Worker Spawning & Coordination):
- Sub-workers produce artifacts with specific types: style_profile, evidence_bundle, draft_candidates, review_feedback
- Artifact writer validates artifacts before writing (schema validation)
- Validation failures trigger Worker fallback strategy (same as timeout)

From Story 3.1 (Decision Event Capture):
- Validation failures logged as `artifact_validation_failed` decision events
- Event includes validation errors and severity (critical)

From Story 3.3 (Tool Usage Logging):
- Tool results are validated (if applicable to artifact schema)
- Validation errors prevent tool results from being stored

**Key Insight:** Schema validation is a runtime gate that prevents bad data from entering the system. Validation happens synchronously before DynamoDB write, and validation failures trigger Worker fallback strategies (same as sub-worker timeouts).

### Data Models

**ValidationResult Schema:**
```python
{
    "is_valid": "Boolean",
    "errors": ["Array of error strings"],
    "warnings": ["Array of warning strings"]
}
```

**ArtifactValidationError Schema:**
```python
{
    "error_type": "artifact_validation_failed",
    "artifact_type": "String (e.g., 'style_profile')",
    "schema_version": "String (e.g., 'v1')",
    "validation_errors": ["Array of error strings"],
    "severity": "critical"
}
```

**Note:** Uses `meta.artifact_type` and `meta.schema_version` fields (not `artifact_version`).

**Schema File Structure (Example - style_profile_v1.schema.json):**
```json
{
  "$schema": "http://json-schema.org/draft-07/schema#",
  "type": "object",
  "required": ["meta", "data", "quality_signals", "provenance"],
  "properties": {
    "meta": {
      "type": "object",
      "required": ["artifact_id", "job_id", "iteration", "task_id", "artifact_type", "schema_version"],
      "properties": {
        "artifact_id": {"type": "string", "format": "uuid"},
        "job_id": {"type": "string", "format": "uuid"},
        "iteration": {"type": "integer", "minimum": 0, "maximum": 4},
        "task_id": {"type": "string"},
        "parent_task_id": {"type": ["string", "null"]},
        "artifact_type": {"type": "string", "enum": ["style_profile", "evidence_bundle", "draft_candidates", "review_feedback"]},
        "schema_version": {"type": "string", "pattern": "^v\\d+$"}
      }
    },
    "provenance": {
      "type": "object",
      "required": ["sources"],
      "properties": {
        "sources": {
          "type": "array",
          "minItems": 1,
          "items": {"type": "object"}
        },
        "claims": {
          "type": "array",
          "minItems": 0,
          "items": {"type": "object"}
        }
      }
    },
    "quality_signals": {
      "type": "object",
      "required": ["confidence", "coverage"],
      "properties": {
        "confidence": {"type": "number", "minimum": 0, "maximum": 1},
        "coverage": {"type": "string", "enum": ["comprehensive", "moderate", "limited"]}
      }
    }
  }
}
```

**Note:** 
- `provenance.claims[]` is optional globally (minItems: 0), but required for `evidence_bundle` (enforced in artifact type-specific schema)
- `quality_signals.validation_passed` is NOT included (redundant - if artifact is written, validation implicitly passed)

### API Specifications

**Validation Function:**
- **Function:** `validate_artifact(artifact_data: dict) -> ValidationResult`
- **Input:**
  - `artifact_data`: Full artifact data (dict, must include `meta.artifact_type` and `meta.schema_version`)
- **Output:** ValidationResult with is_valid, errors, warnings
- **Raises:** ArtifactValidationError if validation fails (includes all errors)
- **Behavior:** Synchronous validation (blocking, no async)
- **Schema Lookup:** Loads `${meta.artifact_type}_${meta.schema_version}.schema.json` from `schemas/` directory
- **Version Handling:**
  - If `meta.schema_version` is unknown (future version): Hard fail with ArtifactValidationError
  - If `meta.schema_version` is deprecated (older than latest): Allow but log warning or emit `artifact_schema_deprecated` event

### Technical Constraints

**Validation Timing:**
- Validation happens BEFORE DynamoDB write (validation gate, not post-write check)
- Validation is synchronous (blocking, no async validation)
- If validation fails, do NOT write to DynamoDB (prevent bad data)

**Required Fields:**
- All required fields must be present and valid (meta.artifact_id, meta.job_id, meta.iteration, meta.task_id, provenance.sources[], provenance.claims[], quality_signals.confidence, quality_signals.coverage, quality_signals.validation_passed)
- Validation errors must be human-readable (field path, expected type, actual value)

**Schema Versioning:**
- Version-aware validation (load schema based on `meta.artifact_type` and `meta.schema_version` fields)
- Schema lookup: `${meta.artifact_type}_${meta.schema_version}.schema.json` (deterministic)
- Old schema versions remain for backward compatibility (read-only validation)
- Writers default to latest schema version (from `LATEST_SCHEMA_VERSION_BY_TYPE` constant)
- Writers may emit older versions only if explicitly configured (e.g., replay mode, backfill)
- If artifact specifies deprecated schema_version (older than latest): Allow but log warning or emit `artifact_schema_deprecated` event
- If artifact specifies unknown schema_version (future version): Hard fail with ArtifactValidationError

**Error Handling:**
- Collect all validation errors (don't fail on first error, return array of all errors)
- Error format: `"{field_path}: expected {expected_type}, got {actual_value}"`
- Validation failures trigger Worker fallback strategy (same as sub-worker timeout)

**Event Tracking:**
- All validation failures logged as `artifact_validation_failed` decision events
- Event includes validation errors and severity (critical)
- Dashboard shows validation failure rate by sub-worker type
- **CloudWatch alarm:** Alert if validation failure rate >5% for any sub-worker type:
  - Time window: 15 minutes (rolling window)
  - Minimum sample size: At least 20 attempts (to prevent spam from low-volume periods)
  - Attempt definition: A sub-worker invocation that returned any artifact (completed or failed) - counts as one attempt
  - Failure definition: A sub-worker invocation that produced an invalid artifact (validation failed) - counts as one failure
  - Rate calculation: (failures / attempts) * 100, only if attempts >= 20 in the 15-minute window
  - Alarm triggers if: rate >5% AND attempts >= 20 in the 15-minute window
